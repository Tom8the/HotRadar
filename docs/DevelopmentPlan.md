# HotRadar 第一阶段开发方案

更新于 2026-10-14。HotRadar 采用今日热榜的平台榜单组织方式，在现有 Python/FastAPI 与 Next.js 骨架上开发，重点补齐 MCN 所需的跨平台事件、七天趋势与具体爆款内容。首期不做内容制作或发布。

## 已确定的实现方向

1. 首页采用分类导航与多平台榜单卡片，支持关注、搜索、局部刷新和来源状态，保留原文入口。
2. 热榜、事件、具体内容使用不同对象和页面。抖音话题热榜不能作为抖音爆款视频池。
3. 优先借鉴 MIT 许可的 NewsNow 和 DailyHotApi 的来源组织与解析方法，由 Python 适配器实现；前端继续使用 Next.js，不整体 Fork 或迁入 Vue 应用。
4. 排名历史、采样覆盖、事件聚合和趋势计算由 HotRadar 自己持久化与实现。TrendRadar 作为模型和分析方法参考，当前不复制其 GPL 代码。
5. 首期数据层定为 PostgreSQL 16 与 JSONB，配合 SQLAlchemy 2、Alembic。保留现有 API、前端和独立 Worker 三个进程，不引入 MongoDB、Redis、向量库或微服务。
6. 用户确认UI后指定当前只接入抖音和微博，其他平台以后再加。原百度/B站优先安排被替代。M1已完成两平台真实闭环，状态见Roadmap。

选型证据与许可证见 [开源项目核查](References.md)，来源能力与接口边界见 [数据接入方案](DataSources.md)。

## 今日热榜的参考范围

本次读取了[首页](https://tophub.today/)、[使用指南](https://tophub.today/help)、[微博榜单详情](https://tophub.today/n/KqndgxeLl9)、[热文库](https://tophub.today/trending)与[官方 API 文档](https://www.tophubdata.com/documentation)。网页 HTML 可以核实功能入口、榜单条目、更新时间与登录提示；浏览器整页读取超时，未完成视觉截图及交互测试。

| 参考功能 | HotRadar 的处理 |

| 热文库 | 转为具体内容池；当前两平台话题榜不提供视频数据，内容接口后续验证，B站暂缓 |
| 追踪与过滤 | 首期提供关注事件、关键词过滤；通知机器人留待后续 |

今日热榜热文库的内容需登录才可见，历史数据等功能在指南中列为 VIP 权益；本次没有验证这些功能的账户内行为。TopList/mo.fish 是另一个开源项目，不能据同名认定它是 tophub.today 的源码。

## 页面与操作

主导航：**热榜总览、热点事件、趋势观察、爆款内容、我的关注**。页面头部保留关键词搜索、时间范围、平台与分类筛选、采集状态，以及工作台/大屏切换。

### 热榜总览

采用今日热榜的信息密度：平台图标与榜单名、更新时间、排名列表、源内指标和“更多”入口。常规桌面布局建议 3～4 列卡片，大屏建议 4～6 列，按分辨率自适应；每卡默认 10～15 条。以上为 HotRadar 设计尺寸，不是已实测的今日热榜断点。

M2已增加浏览器本地分组、卡片拖动/按钮排序、偏好恢复、关键词与广告过滤、规则分类、单卡读取和暂停自动读取。所有刷新只读数据库，强制采集不暴露给浏览器。标题打开原始来源，详情另设按钮；筛选不改变源排名，分类明确注明关键词规则。

顶部统计只显示有定义的“有效来源、过期来源、今日新收录、跨平台事件”等，禁止使用无来源的全网覆盖数字。

### 热点事件

M3已实现保守长标题与48小时观测窗口关联候选、跨平台优先排序、人工合并/拆分/恢复、来源摘要和关注标签。侧栏保留原始标题、最后出现榜位、是否仍在选定日期末次榜单、指标口径与原文。自动关联仍需核对；实体/行为语义模型和事件领域判断尚未上线。

同词不同事件不能仅按关键词合并，转载网站也不自动算独立平台。传播热度和事实可靠性分别展示，热度高不表示事实已核实。

### 趋势观察

M4已实现当日、前一日、近七天与最多31日自定义窗口。默认七天包含顶部所选日及前六日，按北京时间分日；每源采样日数及缺口可见。榜位纵轴越靠上越靠前，源内指标独立绘图，首末观测跨度不称完整在榜时长。默认缩放实际采样，并可查看完整日期留白。

图中断采为缺口，成功榜单中未见该条目为“未在采集榜单内”，不能画成热度零。只采到两天就展示两天；历史导入必须注明来源和粒度，不冒充自行连续采样。

### 爆款内容

卡片包含封面、标题、作者、平台、发布时间、采样时间、原始链接及可用的播放、点赞、评论、分享指标。榜单入选只标“平台热门”，有至少两个可比指标样本后再显示新增量或增长速度。

内容按真实采样时间展示，暂不跨平台混排播放数。缺失指标显示“来源未提供”，禁止从热度字符串还原播放量。2026-10-14内容池保留人工观察，并已验证启用微博热门与抖音精选正常会话采集（默认30分钟）。当前不显示封面、播放量或增长，详见DouyinSdkAcceptance.md；精选包含旧内容，推荐不代表确认爆款，事件人工关联属于M3。

### 我的关注与大屏

首期本地保存平台卡片顺序、主题和筛选偏好；关注事件与标签在项目数据库保存为默认工作区。部署访问控制确定前仅开放本机开发，不把单工作区偏好描述成多用户权限系统。

大屏隐藏编辑操作，放大榜单和趋势，保留时间与来源异常提示；轮播可暂停，自动刷新不打断阅读。收藏和关键词跟踪只服务于观察，不自动生成或发布内容。

## 数据与调度

按照来源、榜单、条目、采样批次、事件、内容指标和关注关系建模，具体表及时间语义见 [技术架构](Architecture.md)。存储原始响应的业务数据，剔除 Cookie、Authorization 和其他凭据。

热榜初始建议每 15 分钟采集一次，RSS 每 30～60 分钟；实际频率按来源能力调整。来源并发 1、有限重试与退避，单源连续失败可暂停。调度器使用数据库幂等键和锁，页面刷新不新建调度任务。

每次记录请求时间、可用上游时间、缓存、状态和条数；缓存不生成增长比较。M1快照统计表示持久化观测批次，不称为独立新数据次数。30天原始/90天排名是后续保留策略，清理器未实现；M1保留全部实际观测。

排名上升用前次榜位减当前榜位表示；新增量按同一内容、同一平台、同一指标计算。指标回撤、内容删除或采样中断作为异常，不能自动解释为负传播。

M3/M4展示源内排名、平台数、观测起止、真实曲线及覆盖，M4只对末两次可比采样计算变化，不将观测跨度称为完整在榜时长。综合分仍需离线回放评估，不沿用未校准权重，也不称为爆款预测。

按用户最新要求，M4先用现有真实历史交付功能，明确不足七天；持续留存后再做七个自然日覆盖和稳定性验收，不能用一次性模拟数据替代。

按单人开发估算，M1约3～4个工作日，M2约2～3日，M3约3～5日，M4约2～3日；这是排期建议，不含平台授权或接口失效等待。摘要、中文事件聚合质量及来源稳定性可能影响周期。无AI摘要时仍可浏览原始榜单和来源列表。

## 功能验证重点

- 同一批次重复执行不重复入库；采样失败、合法空榜、缓存与部分解析失败可区分。
- 时间边界覆盖北京时间午夜、今天和最近七天；缺失指标与真实零值分开。
- 比较窗口不同、上游缓存重复、指标下降、榜单删项时不产生误导性增长。
- 中文近似标题不能直接等同同一事件；抽检跨平台合并，合并错误可以纠正。
- 页面逐一验证卡片刷新、排序恢复、来源详情、原文跳转、筛选、断采提示与大屏暂停。
- 至少持续观察24小时来源稳定性，再进入七天验收；单次请求成功只作为可行性样本。
