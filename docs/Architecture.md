## 规划数据流

来源适配器 → 原始快照 → 字段规范化 → 内容去重 → 事件聚类 → 热度与趋势计算 → API → 热点大屏。

保留每个平台的原始指标和采样时间。摘要引用采集记录；相似事件聚合保存可追溯关系。失败、重试和来源健康状态独立记录。

## 核心数据模型

| 表 | 关键内容与约束 |
|---|---|
| sources | 平台、提供方、首页与访问方式；健康状态由采集任务和快照计算，不存平台凭据 |
| boards | 唯一榜单ID、source_id、类型、解析版本、采集间隔、启停；两个平台的总榜及抖音无锡榜，三个独立榜单ID |
| collection_runs | board_id、唯一job_key、创建/开始/结束、状态、尝试次数、错误及解析版本；缓存/上游时间在快照表 |
| raw_payloads | JSONB业务数据、响应hash、来源与解析版本；剔除凭据，可被多个观测引用 |
| board_snapshots | 成功观测时间、批次、原始响应引用、有效条数、覆盖与缓存状态；一次成功批次唯一 |
| items | board+外部ID唯一、链接、topic类型、最新标题、首次/最近观测；微博使用源内word作ID，非全局标题键 |
| snapshot_items | 不可变标题、链接、源排名、展示序号、置顶、flags、指标、可用来源时间；同快照条目唯一 |
| events（M3） | 观察事件标题、关系版本、人工保护、默认工作区关注及标签 |
| event_members（M3） | item_id主键保证一条来源话题只归属一个当前事件；关联依据、算法版本和原始匹配证据ID |
| event_changes（M3） | 操作类型、原因、时间、before/after成员及配置、恢复操作引用；不删除审计 |
| event_summaries（M3） | event+signature唯一、Provider/版本、输入证据ID、摘录及观测概括、生成时间 |
| event_processed_snapshots（M3） | 已处理快照主键、算法版本和处理时间，重启及回填幂等 |
| content_observations（来源核查） | 仅两平台；不可变人工/正常会话观察、内容ID、观测时间、业务JSON、方法/版本及唯一证据SHA-256；不混入topic表 |
| content_source_settings（会话采集） | source_id、enabled、独立周期、verified_at及无凭据验证/暂停记录；新库默认关闭 |
| content_collection_runs（会话采集） | 唯一job_key、source_id、开始/结束、状态、有效/拒绝数量、观察ID、版本及安全错误码；失败数量可空 |
| 独立watchlists与preferences表（暂缓） | 单工作区事件关注/标签已在events实现，平台与筛选偏好由浏览器保存 |
| source_setting_changes（M2已实现） | board、变更时间、before/after配置；无密钥或Cookie |

索引优先覆盖`(board_id, observed_at)`、`(item_id, observed_at)`、事件时间窗口与唯一外部ID。原始数据按hash去重存储，但真正独立的重复观测仍保留；上游缓存重复不虚增独立样本数。

## 采集与处理职责

适配器返回统一批次，包含条目、原始业务数据、请求时间、上游时间与缓存信息；shape错误和解析异常必须失败，不能返回成功空榜。合法空榜、部分解析失败、请求失败和过期缓存分开记录。

Worker通过数据库任务领取与锁限制每源并发，定期创建任务采用调度分桶幂等键。API只查询持久化读模型，不在页面请求期间直接抓平台。首期用独立Worker进程内的定时循环，无需外部调度平台。

M3复用board+external_id来源去重，比较实际观测中此前48小时另一平台的不可变标题；不使用未来最新Item标题决定旧观测关系。长标题一致、完整长主题包含或长片段高度一致才创建自动关联候选，多个候选事件冲突时保持独立；数字不同、短关键词及其他文字相似仅用于人工建议。自动结果待核对，不声称实体/行为语义模型或事实置信度已实现。

M3采用local-extractive/source-extractive-v2确定性摘要函数：按事件与日期选每条来源话题的最后真实观测，概括平台、条目和留存记录数，引用原始标题，保留输入SnapshotItem ID、model=null和内容签名。未读取正文或调用LLM。旧摘要版本保留；生成在Worker、人工操作或明确的摘要回填命令中执行，API读视图不写库。

## 趋势与指标

今日按Asia/Shanghai的00:00至当前，近七天包含今日与前六个自然日。存储时间使用UTC带时区类型。平台不同指标不相加，热榜位置与具体视频互动量分开计算。

采集失败、未在成功榜单中出现、源内真实零值和未提供指标是四种不同状态。对前两者保留标记，不统一转为0；图表断采留空。显示上榜持续时间时需说明这是观测范围内的时长，并保留覆盖率。

## 具体内容观察

具体内容来源核查新增迁移20261014_0004及独立不可变content_observations。人工核查CLI验证页面证据后写入；证据JSON是已核对的网页字段，不冒充平台API原始响应。SHA-256约束实现相同证据幂等，事务锁按平台与内容ID串行；同一内容多次真实观察各自保留，日期读模型不覆盖旧值。发布时间保存页面文本/时区/分钟精度，观测时间使用带时区UTC；不补秒级时间或播放量。

内容页展示人工与两平台正常会话精选/热门候选，未定义爆款阈值；增长比较和内容与事件关联未接入。GET /api/v1/contents按北京时间采样日期只读最后观察，Next.js代理不写数据、不请求平台。原topic、事件算法及趋势口径保持独立；没有依赖变更。

content_collection.py从微博热门推荐statuses提取真实内容，启用前另校验真实详情；douyin_content.py使用正常页面SDK确认的POST /aweme/v2/web/module/feed/及精选全部分类非认证参数，请求本机正常Cookie与实际UIFID，不回放签名。发布时间来自create_time秒级Unix时间，统计来自statistics，播放量不采纳。仅视频类型0/4、完整身份/时间/标题与可用互动通过；广告、非视频及不完整条目跳过。描述可能被来源截断，保留原值并标注。

两个来源共享独立内容任务框架：每源PG advisory事务锁、唯一调度键、失败批次savepoint回滚、安全错误码及不可变观察。会话失效/上游拒绝仅关闭该来源配置，历史留存。Worker每源检查enabled、verified_at与最后任务时间，默认30分钟；两来源独立周期且不改变topic配置。业务字段白名单、任务ID和SHA-256可追溯。现有0005支持本次接入，无迁移或依赖变更。

session_store.py使用stdlib调用Windows当前用户DPAPI，密文原子写入data/sessions；先限制目录ACL。Cookie域仅限对应两平台，过期项不发送，HTTPS客户端禁止重定向。API只返回本机已保存布尔状态，不返回凭据或其值。具体内容停启通过本机CLI，页面来源管理仍只管理话题榜。运行及实测边界见会话采集验收（本地留档 `SessionCollectionAcceptance.md`）。

## M2实现

迁移20261014_0002新增配置审计表和可空的快照interval_seconds，旧快照保持原值，新观测保存任务开始时采集周期。比较采用两次观测周期的较小值；M1未记录周期的旧快照使用900秒，不因当前配置调大而放宽旧比较窗口。

GET /api/v1/source-management返回两源配置、真实最近24小时任务、最近错误与配置审计；统计窗口不等于完整连续覆盖。PATCH /api/v1/boards/{id}/settings仅支持两榜单启停和900/1800/3600秒；行锁事务和配置记录同步写入，无变化不增加记录。Worker按数据库配置检查，暂停不清除历史；seed不覆盖既有配置。

Next.js /api/sources进行本机同源写入校验，按实际Host匹配Origin并限制回环主机，拒绝缺失Origin和外部Origin；GET不要求修改权限。服务仍只绑定127.0.0.1。/api/radar?board={id}&view=1&date={date}读取单卡视图；不创建采集任务。

工作台偏好使用浏览器hotradar-preferences-v2，兼容v1。分组、成员、ID、顺序及筛选输入规范化，未知平台被剔除。归类为明确的关键词规则；条目过滤保留排名、指标及引用，卡片排序只调整展示。自动读取与采集独立。异步详情采用序号避免旧响应覆盖新选择，侧栏支持焦点约束和Escape关闭。

## M1实现边界

原始响应按board+SHA256去重，独立观测仍留存snapshot_items；更新最新条目不覆盖历史标题、链接和指标。榜位箭头只比较前次完整、非缓存且间隔不超过三倍采集周期的快照，不代表热度增速。缺失指标为null，真实0保留。

Worker使用PG advisory lock限制榜单并发，调度键唯一，最多三次重试；近24小时未完成任务重启恢复。HTTP Age提示缓存时保存标记，不生成增长比较。单源熔断和自动数据清理尚未实现；30/90天保留策略待后续，当前保留全部实际观测。

## M3一致性与修正

Worker每轮采集提交后处理待聚合快照，空闲轮也恢复未完成聚合。单独事务及统一PG advisory事务锁串行化聚合与所有人工操作；聚合失败回滚处理标记，原始榜单仍可读，下轮重试。GET事件列表/详情使用REPEATABLE READ READ ONLY事务，避免混读不同关系版本。

合并目标保留标题并纳入全部成员，继承关注和标签；标签超过12个则回滚而不截断。拆分只接受当前成员的非空真子集。涉及事件提升版本并启用人工保护，后续新别名保持独立；新采样仍更新原有成员的来源证据。

恢复要求所有涉及事件当前配置/版本/成员与操作after一致，原操作不可重复恢复；恢复新增审计并递增版本，不回退版本号，不覆盖后续关注、标签或成员修改。冲突返回409，用户刷新再按当前来源手动修正。空事件保留用于追溯，在日期列表中隐藏。历史页面采用最新关系，尚无任意时刻关系回放界面；前后关系在审计内可查。

摘要按event+signature缓存，列表批量读取成员数量与当前摘要版本。正文摘要、LLM、统一热度、事实核查、自动预测及增长模型未启用。

## M4读模型与绘图

trends.py从既有BoardSnapshot、SnapshotItem、CollectionRun、SourceSettingChange及当前EventMember关系构建读模型，无新增数据库表或依赖。两个趋势GET使用REPEATABLE READ READ ONLY事务；日期范围最多31个自然日，结束日期不能超过今日，今天截断至读取时点。

每条来源成员分别遍历其平台的实际快照和失败/未完成任务。真实条目保留evidence_id、snapshot_id、run_id、原始标题/链接、源排名、指标对象、解析版本、缓存与采样周期。完整快照未见非广告成员记not_on_board，部分解析未见记unknown_partial；失败和未完成任务没有伪造快照。没有计划补点，也不将状态转成0。

覆盖按北京时间日期统计真实快照，有快照日期数不等于全天覆盖。首次成功留存之前留空，实际配置审计重建暂停区间；相邻采样超过周期1.5倍识别缺口，及时周期变更可调整下一次预期采样。旧快照未记录周期时采用当时默认900秒并披露。此规则是缺口提示，不构成服务连续性证明。

connectable_before仅在相邻两点均有成员、完整、未标缓存、解析版本相同、时间间隔在两周期较小值1.5倍内，且没有跨过暂停/缺口时成立。榜位或指标缺失继续断线；指标单位/提供方/定义不同于末次口径的点保留在原始记录中，但不混入该指标曲线。末两次可比点提供榜位差、指标差、可计算的百分比、窗口及证据ID；基期0不算百分比，负差仅作源内变化。

前端使用SVG和ResizeObserver按容器实际宽度绘图，无图表依赖；同事件多个来源话题各自成曲线，最多同时选8条，指标独立面板。全部原始点用于折线，超过240点时减少点标记，记录和采样点选择仍保留全部值。默认缩放至实际采样区间，也可展示完整日期窗口及无数据区域。

大屏在宽屏将来源覆盖/健康状态放侧栏，主区域显示当前事件与曲线；每15秒轮播，可单独暂停或前后切换，退出时清除轮播。自动读取仍由工作台控制，暂停不会停止Worker。异步列表/事件读取使用序号避免旧响应覆盖新选择，读取失败保留明确时间的旧视图。

用户在“今日”并开启自动读取时，页面每30秒检查北京时间日期，午夜自动推进；显式历史日期和暂停读取不自动改动。跨午夜真实运行及连续七天覆盖仍需自然时间验证，日期边界已在独立测试中覆盖。
